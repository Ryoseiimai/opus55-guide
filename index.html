Opus 5.5 のじょうずな頼み方

Anthropic の公式ブログ「Getting the most out of Opus 5.5」の要点を、プログラミングを知らない人にも伝わるよう、身近なたとえと実例に置きかえてまとめました。

元記事（英語）：claude.dev/blog/getting-the-most-out-of-opus-5-5
※全文訳ではなく、内容を要約した解説です。例はこのページ独自のものです。

まず、この3つだけ覚えてください

Opus 5.5 は「優秀で、長時間ひとりで働ける新人」のようなAIです。細かく指示を小分けにするより、仕事をまるごと任せる方が力を発揮します。

まとめて渡す仕事は小出しにせず、全体を1回で伝える
「よく考えて」は不要言わなくても毎回ちゃんと考えてから答える
終わったら要点から読む「あなたの判断待ち」の部分を最初に確認する

1. 頼み方のコツ

「どうなったら完成か」を先に言う

ゴールと、止まるタイミングを1回のメッセージで伝えます。完成の基準がはっきりしていると、AIは途中で迷わず最後までやり切れます。

あいまい来月の社内イベントの準備をお願い
伝わる来月の社内イベントの準備をお願い。完成＝案内文・当日の進行表・持ち物リストの3点がそろっていること。会場の予約だけは私がやるので、そこに来たら止めて

「じっくり考えて」は消してOK

Opus 5.5 はもともと答える前に必ず考えます。わざわざ「よく考えて」と書く必要はありません。元記事では、この一言を消すと答え始めるまでが速くなり、質は落ちなかったと紹介されています。

逆に、簡単な質問なら「すぐ答えて」と添えると、さっと返ってきます。

今までのクセステップバイステップで慎重に考えて、会議の議事録を要約して
これで十分会議の議事録を要約して。決まったことと、次に誰が何をするかを分けて

作業中でも、追加の指示を送っていい

長い作業の途中で「あ、これも」と思ったら、止めずにそのままメッセージを送れます。最初からやり直させるより、ずっと手間が少なく済みます。

たとえば50社分の取引先リストを整理させている途中で「ついでに、住所が古そうな会社には印をつけておいて」と送る

デザインは「使ってほしくないもの」を具体的に

「ありきたりにしないで」のようなぼんやりした言い方より、避けたい見た目を名指しで並べる方がうまくいきます。

ぼんやりAIっぽくない、おしゃれなチラシにして
具体的クリーム色の背景、斜体の強調、丸いボタン、絵文字の見出しは使わないで。色は白黒＋紺1色だけ

2. 長い仕事を任せるときのコツ

ここは主に、パソコンで自動作業をさせる「Claude Code」向けの話です。ふだんのチャット利用なら読み飛ばしても大丈夫です。

「いつ止まって聞くか」をルールにしておく

任せっぱなしで困るのは、勝手に大事なものを消されたり、逆に細かいことをいちいち聞かれたりすることです。「自分がいないと進めないときと、消す・上書きするなど取り返しのつかない操作の前だけ聞いて」と、あらかじめ決めておきます。

Claude Code では、このルールを CLAUDE.md という設定メモに書いておけば毎回守ってくれます。危ない操作の確認画面は、念のため有効のままにしておくのがおすすめです。

大きな仕事は「チームで分担」させる

大量の書類チェックのような仕事は、AIに自分の分身（サブエージェント）を何人も立てさせ、手分けして進めさせられます。最後に、それぞれの報告の裏付けを確かめたうえで、表にまとめて提出させるのがコツです。

たとえば「過去1年分の契約書30本を、担当を分けて読んで。更新日と解約条件を1つの表にまとめて。表に書く前に、原文のどこに書いてあったか必ず確認して」

やることリストはファイルに書かせる

長い作業では、会話が長くなるほど前半の内容が圧縮されて薄れていきます。チェックリストを別のファイル（たとえば TASKS.md）に書かせておけば、AIも人も「どこまで終わったか」をすぐ確認できます。

3. 結果の確かめ方

最初に「あなた待ち」の部分を読む

長い作業が終わったら、全部を上から読む前に「あなたの判断や承認が必要なこと」だけ先に確認します。そこが止まっていると、他が全部できていても先に進めないからです。

報告の形も指定できます。たとえば「最後の報告は『あなた待ち／変えたこと／見つけたこと』の3つに分けて」と決めておくと、毎回読みやすくなります。

出す前に、AIにもう一度チェックさせる

できあがったものを人に出す前に、別の目線でAIに見直させます。Opus 5.5 は見落としが少なく、的外れな指摘も少ないと紹介されています。「全部ダメ出しして」ではなく、「これは止めるべき、という問題だけ、場所つきで」と絞るのがコツです。

指摘が多すぎるこの提案書の改善点を全部出して
本当に大事なものだけこの提案書を社長に出す前に、このままでは出せないレベルの問題だけ挙げて。ページ番号も添えて

「見つからなかったこと」も書かせる

調べものを頼むときは、「わからなかったことは、わからなかったと書いて」「どこをどう探したかも書いて」と添えます。AIが推測で空白を埋めてしまうのを防げます。

たとえば「近所の貸会議室を5つ調べて料金を表にして。料金が載っていなかった所は空欄にして『未確認』と書いて。見たサイトも一緒に」

4. チャット（Claude アプリ）での使い方

グラフや画面はスクショのまま貼る

数字を手で打ち直す必要はありません。Opus 5.5 は図表の読み取りが正確になり、「どこに何があるか」の理解も強くなっています。

たとえば売上グラフのスクショを貼って「前年より落ちている月はどこ？ 理由の候補も3つ」と聞く

長い書類の「食い違い探し」を頼む

数字・日付・名前が途中で食い違っていないかのチェックが得意です。元記事のテストでは、日付と曜日のずれや、グラフと本文で数字が合わない箇所を見つけています。

たとえば「この40ページの報告書で、同じはずの数字・日付・人名が食い違っている所を全部挙げて」

「骨組み」ではなく「完成品」を頼む

「構成案を出して」で止めず、そのまま共有できる表計算ファイルや文書として作ってもらう方が、あとで手直しする量が減ります。

手間が残る来月の予算表の項目案を考えて
すぐ使える来月の予算表をスプレッドシートで作って。合計欄は自動計算にして

長いチャットでは「前の話は決定済み」と伝える

やり取りが長くなると、AIが前の話題を蒸し返すことがあります。「答えが出たものは決定済みとして扱って、今の質問に集中して」と添えると落ち着きます。ただし、長い分析をいっしょに続けている場合は、あえて言わなくて構いません。

5. メッセージが「制限」に引っかかったら

安全のための仕組みで、まれに質問が引っかかることがあります。そのときの動きは次のとおりです。

使っている場所起きることどうすればいい
Claude アプリ自動で1つ前のモデルに切り替わる新しいチャットでやり直せる。設定で「切り替える前に確認」にも変えられる
Claude Code同じく別モデルに切り替わる/model で戻す。誤判定なら /feedback で報告

引っかかりやすいのは「あなたの頭の中の考えをそのまま再現して見せて」のような頼み方です。代わりに「理由を3文で説明して」のように形を変えて聞くと通りやすくなります。

6. もっと速く返してほしいとき

1回ずつ返事を読みながら進める作業なら「ファストモード」が便利です。料金は割高になりますが、返事が速くなります。Claude Code では /fast で切り替えられます。

逆に、まとめて任せて放っておく仕事なら、通常モードで十分です。
